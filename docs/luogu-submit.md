# 洛谷提交：书签方案

> 目标：把 OIworld 里写的代码交到洛谷评测，**不引入服务器、也不要求安装浏览器扩展**。

实现方式：一个 `javascript:` 书签（源码在 `src/luogu/bookmarklet.ts`）。
你在洛谷题目页点它，它就**在洛谷自己的页面里**发提交请求 —— 于是同源、天然带着你的登录态，
不需要跨域、也不需要伪造 `Cookie` 头。

---

## 1. 为什么必须这样（浏览器硬规则）

| 实测项 | 结果 | 含义 |
| --- | --- | --- |
| `OPTIONS /fe/api/problem/submit/P1001`（带 `Origin`） | `403`，响应里**没有任何 `Access-Control-Allow-*` 头** | 本站页面读不到洛谷的任何响应 |
| `Set-Cookie: __client_id=…` | `HttpOnly; Secure; SameSite=None` | 网页 JS（哪怕在洛谷页面上）也读不到它 |
| 在 fetch/XHR 里设 `Cookie` 头 | 浏览器直接忽略 | `Cookie` 是禁止请求头 |

所以 vjudge 那种"粘一次 Cookie 就行"的做法，靠的是**它自己的服务器**代发请求。
本项目不引入服务器，于是把"代发请求"这一步交给书签：**在洛谷的页面上下文里执行**。

```
OIworld 题目页                     洛谷题目页
┌───────────────────────┐         ┌────────────────────────────┐
│ 编辑器里的代码          │  ①复制   │ 地址栏 ?oiworld=<payload>   │
│ 「书签提交」按钮 ───────┼────────▶│                            │
└───────────────────────┘  ②打开   │  ③点书签 → 页面内 fetch      │
                                   │     POST /fe/api/problem/  │
                                   │          submit/{pid}      │
                                   │  ④轮询 /record/{rid} 并浮层  │
                                   │     显示 AC / WA / …        │
                                   └────────────────────────────┘
```

## 2. 书签做了什么

1. 从地址栏 `?oiworld=<base64url>` 解出 `{code, lang, enableO2}`（解不出来就读剪贴板，再不行弹框让你粘贴）；
2. 读当前页面的 `<meta name="csrf-token">`；
3. `POST /fe/api/problem/submit/{pid}`，头带 `X-CSRF-TOKEN`、`Content-Type: application/json`；
4. 用返回的 `rid` 轮询 `/record/{rid}?_contentOnly=1`，在页面右上角浮层里显示评测状态
   （AC / WA / TLE / MLE / RE / CE…）并给出记录链接；
5. 在非题目页被点开时只提示"请先在洛谷打开一道题目的页面"，不发任何请求。

用到的接口都是洛谷自己的前端在用的（提交接口的请求体是 `{lang, code, enableO2}`，
响应里给 `rid`；状态枚举来自 `/_lfe/config` 的 `RecordStatus`）。

## 3. 代价：本站读不到评测结果

书签跑在洛谷的页面里，结果只能显示在**那边**。OIworld 这边因为跨站限制：

- **看不到评测结果**：结果在洛谷页面右上角的浮层里；
- **看不到提交记录**：没有扩展就没法读 `/record/list`（题号旁边给了"去洛谷看提交记录"的链接）；
- **通过与否由你确认**：在洛谷拿到 AC 后，回题目页点「我已在洛谷 AC · 标记本题通过」，
  才会解锁下一题（Pro 靶场）。

> 早期版本提供过可选方案：装一次油猴脚本，由扩展用 `GM_xmlhttpRequest` 代发请求，
> 于是能在本站提交、轮询结果、拉取提交记录。为了不引入安装负担已经移除。

## 4. 安全边界

| 边界 | 做法 |
| --- | --- |
| 在哪些页面生效 | 只处理地址形如 `/problem/{pid}` 的洛谷页面；其它页面点了只给提示 |
| 读什么 | 只读当前页面的 csrf-token 与地址栏/剪贴板里你自己的代码；不读表单、不读其它站点 |
| 发到哪里 | 只请求 `luogu.com.cn` 自己的接口；没有任何第三方域名 |
| 能不能审计 | 源码是仓库里的纯文本 `src/luogu/bookmarklet.ts`（约 5.6KB），可以逐行读、也可以自己改 |
| 本站存了什么 | 只存题号 / 语言 / O2 开关（`localStorage` 的 `oiworld:luogu`）；**不存任何凭据** |

## 5. 题面与洛谷原题的对齐

书签提交有一个前提：**你写的程序要符合洛谷那道题的输入输出格式**。
OIworld 的题面是自撰的，格式未必与洛谷相同（踩过这个坑：参考题解交上去全 WA）。
所以题目数据里有 `luogu_aligned` 标记，含义是"本题参考题解能原样通过洛谷那道题的样例"：

```bash
npm run validate:pro-luogu     # 取洛谷公开样例 → clang-wasm 编译参考题解 → 逐样例比对
```

- **已对齐**（Pro 阶段一 6/6）：面板自动预填题号，并标注"题面已与洛谷对齐"；
- **未对齐**：不预填题号，并提示"本题输入输出格式可能与洛谷不同，想交洛谷先读洛谷题面"。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点书签没反应 | 不在题目页 / 书签地址被截断 | 确认地址形如 `/problem/P1001`；重新拖一次书签 |
| 提示"没有登录洛谷" | 浏览器没有登录 | 先登录 luogu.com.cn |
| 提示"要求人机验证" | 洛谷对部分提交要验证码 | 先在洛谷手动交一次这道题，再用书签 |
| 提交成功但结果不对 | 本题格式与洛谷原题不同 | 读洛谷题面，把输入输出改成洛谷的格式 |

## 7. 可以继续做的

1. 把 Pro 阶段二 ~ 七的 36 道题按同一流程对齐（取洛谷题面与样例 → 改写题面规格/题解/测试用例 → 过样例门禁）；
2. 给 C++ / Python / Java 三个基础靶场也标注"是否与洛谷对齐"（现在只标了题号）；
3. 如果以后想要"在本站直接看评测结果与提交记录"，可以把油猴桥接方案作为**可选**功能加回来。
